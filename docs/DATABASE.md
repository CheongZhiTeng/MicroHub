# Database design

Migrations are additive and module-scoped. `202611140001_identity_membership.sql` creates the identity/membership foundation; `202611140002_private_storage.sql` creates a private bucket with no application object-access policies. The rest of this document is the preserved schema plan, not a claim that homework, attendance or later-phase tables already exist.

## Implemented schema

| Table                   | Keys and data                                                                                             | Access                                                                                                           |
| ----------------------- | --------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| profiles                | UUID PK/FK auth.users; unique six-digit student_id; name, class; active/suspended; created_at, updated_at | Verified self; active club roster; authorized admin. Self may update name/class columns only.                    |
| platform_roles          | user_id PK/FK; member/admin/super_admin; updated_at                                                       | Self after verification; roles visible to active members. Mutation only via Super Admin RPC or secure bootstrap. |
| club_settings           | singleton boolean PK with CHECK true; name, description, updated_at                                       | Active member read; Super Admin RPC update. Exactly one seeded row, no delete grant.                             |
| committee_positions     | UUID PK, unique title                                                                                     | Active member read. Management UI/RPC deferred to the next MVP increment.                                        |
| memberships             | user_id PK/FK; active/inactive; committee_position_id FK; joined_at, updated_at                           | Active club members or verified self. No direct client writes.                                                   |
| membership_applications | UUID PK; user_id FK; pending/approved/rejected; reviewer FK/timestamps                                    | Active self or admin; insertion/review via checked RPC. Partial unique index allows only one pending request.    |
| audit_logs              | UUID PK; actor FK; action, target_id, details jsonb, created_at                                           | Super Admin read; server operations append. No authenticated insert/update/delete grants.                        |

All seven public tables have RLS. UUIDs use gen_random_uuid(); auth-provided profile and one-to-one IDs inherit the UUID from the parent. Audit target_id is polymorphic and intentionally has no FK; action identifies the entity. Every other relationship is constrained. Profile/auth deletion is RESTRICT until a retention-aware deletion workflow exists.

`is_verified`, `is_active_user`, `is_member`, `is_admin`, `is_super_admin` read current database state, rather than user-editable JWT claims. Helper functions return only booleans. SECURITY DEFINER functions have an empty search_path and fully qualified relations. Default PUBLIC/anonymous execution is revoked. Relevant FK/filter indexes, timestamps and duplicate guards are in the migration.

RPCs: apply_for_membership (idempotent pending application, profile completeness, 24h retry limit after rejection); review_membership (admin, verified eligible applicant, transaction locks, single decision, membership + audit atomically); admin_set_account (Super Admin, serialized role changes and last-admin protection); update_club (Super Admin + audit). UI invokes review_membership directly. The optional Edge endpoint calls the same RPC using the caller's JWT and verifies the token with Auth; it never uses a service role.

## Planned MVP schema

| Tables                     | Proposed fields and constraints                                                                                                        | Security / module acceptance                                                                                                                                         |
| -------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| invitations                | UUID, token_digest unique, created_by FK, expires_at, max_uses, uses, revoked_at; invitation_redemptions(invitation_id,user_id) unique | High-entropy server-generated token; lock row before redeeming; no plaintext token table access; audit issuance/revocation/redemption.                               |
| assignments                | UUID, title, instructions, due_at timestamptz, creator FK, draft/published/archived, max_score, created_at/updated_at                  | Admin write; active members read published items. Avoid exposing drafts.                                                                                             |
| assignment_files           | UUID, assignment_id FK, private object path unique, mime, bytes, uploader FK                                                           | Admin upload; published assignment's active members may read. Pending uploads are not visible.                                                                       |
| submissions                | UUID, assignment_id FK, owner_id FK, submitted_at; unique(assignment_id,owner_id) for individual submissions                           | Owner or authorized admin only. Submission action freezes an immutable revision.                                                                                     |
| submission_history         | UUID, submission_id FK, revision positive, body, link, submitted_by FK, submitted_at; unique(submission_id,revision)                   | Append via checked RPC; owner/admin read. Revision deadlines derive from server time.                                                                                |
| submission_files           | UUID, revision_id FK, path unique, mime, bytes; uploader FK                                                                            | Access follows the revision/submission; deletion must not corrupt history.                                                                                           |
| grades                     | UUID, submission_id FK unique, revision_id FK, graded_by FK, score >= 0, feedback, private_feedback, graded_at                         | Owner/admin only; validate revision belongs to submission and score <= assignment maximum in RPC. Feedback never enters public Realtime payloads.                    |
| attendance_sessions        | UUID, title, created_by FK, opens_at, late_after, expires_at, closed_at; check ordered timestamps                                      | Members see session metadata; admin creates/closes sessions through RPC.                                                                                             |
| private attendance_secrets | session_id FK unique, code_digest, rotation timestamp                                                                                  | Non-exposed private schema. Server CSPRNG code; keyed hash/pepper stored in backend secrets, not public table. Never return the code in member-visible session data. |
| attendance_attempts        | user_id FK + time bucket unique, attempt_count, blocked_until                                                                          | Private server counter; lock transactionally. Persist failed attempts before returning a normal error result, not a rolled-back exception.                           |
| attendance_records         | UUID, session_id FK, user_id FK, present/late/absent/excused, checked_in_at, source; unique(session_id,user_id)                        | Member reads own records; admin reads roster. Only trusted validator or audited admin correction writes.                                                             |
| attendance_corrections     | UUID, record_id FK, actor FK, old/new status, reason, timestamp                                                                        | Append-only admin audit; absent/excused statuses cannot be self-assigned.                                                                                            |

An active six-digit code must be unique among live sessions or combined with a session ID to avoid ambiguity. Code generation retries collisions. Validation checks open state, expiry, active verified membership, rate limit, constant-time hash comparison and duplicate uniqueness in one server transaction. Return generic invalid/expired responses. Close session deterministically creates absent records from a frozen eligible-member snapshot, not today's roster. These semantics and concurrent tests are required in the attendance increment.

Realtime publications will include only tables/payloads whose RLS and privacy have been verified. The foundation deliberately adds no tables to a publication. Attendance live rosters are enabled during that module, and V1 announcements/notification delivery during theirs. Do not enable Realtime on code secrets, raw audit or private feedback tables.

Offline storage, widgets and recovery procedures also need client/operational work; a table alone does not satisfy those features. Backup scope includes Auth, Postgres and Storage objects. Restore into a separate project and verify identity/FKs/object access before any production recovery.

## File policy and test boundary

`club-private` is private, maximum 10 MiB, MIME allowlist JPEG/PNG/PDF/plain text. It is intentionally inaccessible to authenticated object operations until upload ownership/schema tests ship. Future file rows associate paths with entities; Storage RLS consults that association, not a client-supplied owner folder alone. Validate size, extension, declared MIME and actual bytes in a server upload/finalization step. Signed URLs last at most 60 seconds. Avatar and logo columns arrive with that module.

`npm run test:db` runs the unmodified migrations in PGlite (real PostgreSQL compiled to WASM), with minimal test-only auth.users, auth.uid and storage.buckets fixtures. It verifies constraints, RLS, grants, membership decisions, privacy, last-admin protection, suspension and auditing. It does **not** prove Supabase Auth delivery, Storage API behavior, Edge deployment, Realtime, or concurrent multi-connection safety. Repeat hosted acceptance before marking the module accepted.
