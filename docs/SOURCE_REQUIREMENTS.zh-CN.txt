MicroHub
单一学校学会 · 私人内部管理应用开发总计划
技术栈：Expo / React Native / TypeScript / Supabase / GitHub / Codex
版本：单学会定制版 1.0  |  2026 年 11 月 14 日
一、项目范围与关键决策
仅供一个固定学会内部使用，不开放公众创建社团；部署时由超级管理员设置学会名称、简介及 Logo。
每位成员使用学校邮箱注册：^sa\d{6}@foonyewsa\.edu\.my$；必须验证邮箱所有权。
三级系统角色：Super Admin（最高管理员）、Admin（学会管理人员）、Member（普通成员）。委员会职位与系统权限分开。
不需要多社团选择、跨社团切换、社团发现、跨社团数据隔离或多个社团的申请管理。
原多社团清单中的“创建及管理社团”改为“初始化及管理唯一学会”；“加入社团”改为“申请加入本学会或邀请码加入”；“一个账号加入多个社团”标记为不适用，而非暗中删除。

九、测试与发布
自动化测试：学校邮箱验证、密码重置、RLS、越权访问、作业文件权限、私人评语。
签到边界测试：错误码、过期码、重复提交、并发签到、异常网络、管理员更正。
设备测试：Android 与 iOS、不同屏幕、断网重连、通知授权、语言与主题。
先用 Expo Go 验证基础功能；涉及原生小组件等能力时改用 Development Build。
使用 EAS Build 制作内部测试包；私人使用无需立即公开发布应用商店。
备份恢复必须实际演练；不仅检查“备份任务成功”。
十、开发工作原则与验收
Codex 每次只实现一个模块或一组关联功能，先读已有代码再修改。
每次改动必须包括数据库迁移、RLS 政策、必要测试、README 或文档更新。
所有功能以实际可用为准，不接受只有按钮或占位页面的“完成”。
每个阶段验收后提交 GitHub，保留可回退的稳定版本。
所有 76 项原始需求保留在本文；单学会不适用项必须明确标注，不开发多社团基础设施。
