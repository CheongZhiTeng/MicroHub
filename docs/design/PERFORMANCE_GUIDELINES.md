# 性能复测与目标

创建与最近更新 2026-11-28 · MicroHub 审计基线 `32150ab4bdd46327f52e42e2431dfaa0b5198b95`

先记录基准及环境；无实际设备的性能数值保持待测。使用当前基准、同设备及同样的合成数据，不以单次开发模式分数签收。使用冷／热各至少 5 次的中位数，另外记录慢样本、数据规模及浏览器网络条件。Expo 编译产物大小是构建产物，加载时间需另测。

| 场景                 | 记录并验收                                                                                                      |
| -------------------- | --------------------------------------------------------------------------------------------------------------- |
| Pages 首载           | 同环境记录 TTFB、LCP、首入口可互动时间、压缩 JS 和请求数，目标受控场景中位数不高于基线 +10%，发布需记录膨胀归因 |
| 首页／作业／月历切换 | 记录输入响应、导航到首内容和月历 RPC 次数。去掉同查询多次调用前先证明重复存在，不允许跨会话身份／组缓存命中     |
| 人员、工作队列、讨论 | 用合成 30／100／300／1000 条覆盖列表和分页，虚拟化时使用稳定 ID，避免嵌套同方向 ScrollView 破坏测量与焦点       |
| 成员搜索             | 服务器分页和稳定排序。若使用即时搜索，建议 250ms debounce、取消过期结果；保留 Enter 直接搜索。明确空库和无匹配  |
| 图片与附件           | 缩略图按需请求，预览和下载按授权取签名 URL，失败可重试，敏感签名 URL 不做长期缓存；记录含文件时内存和流量       |
| App 回前台及身份     | 合并确认重复的 focus/AppState 查询；重试只绑定于同用户、同授权范围、同查询。用权限变更矩阵检查旧数据清空        |
| 动画与响应           | 用 React Profiler／Web Performance 查因，确认 selection 和 typing 无整页无关刷新；深浅色都按同一场景复测        |

CI 保留原构建，支持轻量压缩体积监控。以测得基线校对预算；原生首载、JS 帧率和内存的绝对阈值在真实设备采样后记录。协议变更需有受影响代码、理由与回归结果。

## 本轮可复现构建数据

Node v24.22.3，默认使用仓库的 production Expo export。Pages 导出生成 25 个 index.html（含根），主 Web JS 1,120,841 字节，本地 gzip 295,037 字节。gzip 本地大小是同构建版本比较用，实际传输可能由托管层使用不同算法。Android 与 iOS 的单个 Hermes entry 各约 3.9 MB，来源为 Expo 输出的舍入值。这里未测 LCP、INP、内存及实际用户的流量。
