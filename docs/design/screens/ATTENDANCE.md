# 签到逐屏规范

创建与最近更新 2026-11-28 · MicroHub 审计基线 `32150ab4bdd46327f52e42e2431dfaa0b5198b95`

**Proposed**。本页每个界面全部适用 [状态](../INTERACTION_PATTERNS.md)、[响应式](../RESPONSIVE_DESIGN.md)、[双主题](../DESIGN_SYSTEM.md) 和 [无障碍](../ACCESSIBILITY.md)。手机签到码、状态及回执在前，支持粘贴。平板名册和信息区在够宽时并排；桌面显示名单筛选及更正。双主题以文字提供开放/关场及标记，过期不只靠颜色，计时播报避免重复。

## SCR-09 签到首页、本人历史及授权概况

- 路由与实现 `/attendance` · `app/(tabs)/attendance.tsx`。目标角色 活跃成员；管理能力由服务端决定。
- 目的与当前问题。签到与管理的各状态使用模块局部文案。
- 目标布局与主操作。主区域显示开放签到、本人结果、历史。研教用分组概况和发起；桌面增名单入口。
- 组件、次操作和跳转。AttendanceHome、AttendanceOverview、Notice。
- 状态、权限及恢复。无开放签到、权限变更、重复出席、局部统计失败有区分。
- 验收。成员无其他学生历史或代码；只有授权人可以发起，有明确历史回执。
- 设计依据。GC-49 的任务优先；签到属 MicroHub。

## SCR-10 发起普通或活动签到

- 路由与实现 `/attendance-new` · `app/attendance-new.tsx`。目标角色 授权研教及未来全权限。
- 目的与当前问题。普通和 eventId 两条路径，跳转及已有状态需显式。
- 目标布局与主操作。先显示事件／范围、目标对象、起止及策略；预览后发起；已有场次回同一场。
- 组件、次操作和跳转。Attendance API、字段、EventAttendanceButton。
- 状态、权限及恢复。过期修订、取消、重复点击／竞争与网络不确实时刷新对象。
- 验收。同活动不能重复开场；既有合法场次保留；跨组拒绝且无敏感泄露。
- 设计依据。GC-25、26 可参考范围和时间。

## SCR-11 签到会话、名单和更正

- 路由与实现 `/attendance-session` · `app/attendance-session.tsx`。目标角色 成员本人；名单仅有权人员。
- 目的与当前问题。输入码、回执、人员筛选、状态编辑与纠错需分层。
- 目标布局与主操作。成员：状态、截止、输入码、回执；管理：会话控制、受保护码、名单及更正历史。
- 组件、次操作和跳转。AttendanceSession、useAttendanceRead、ConfirmDialog、markLabel。
- 状态、权限及恢复。码错误／过期／频率限制，关场、等待／迟到／缺席、纠错并发、断线同场次重读。
- 验收。保持只显示本人，授权名单与时间，关键修改前原因及回执。
- 设计依据。GC-36、38 可参考状态和历史。
